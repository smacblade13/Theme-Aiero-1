# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is **pnpm** (see `pnpm-lock.yaml`, `pnpm-workspace.yaml`). Do not use npm/yarn.

```bash
pnpm install
pnpm dev      # Next.js dev server at http://localhost:3000
pnpm build    # Static export to ./out/  (next.config.ts sets output: "export")
pnpm start    # Serve production build
pnpm lint     # ESLint (flat config in eslint.config.mjs)
```

There is no test framework configured — do not fabricate test commands.

## Architecture

This is a **standalone static extraction** of a single homepage (`/`) from the "Aiero" AI-agency Next.js theme, generated by an external `scripts/extract-site.mjs` tool (the script itself is *not* in this repo — see README's "Adding inner pages later" note). Only the `/` route is served; everything else has been rewritten to `"#"` and logged in `LINKS.md`. If asked to add a new page, first check `LINKS.md` for the original href — restoring a route means fixing links in `data/mobileMenu.ts`, `data/demo.ts`, `data/footer.ts` and sometimes home-1 components.

### Build target

`next.config.ts` sets `output: "export"` and `images.unoptimized: true`. This means:
- No server code, API routes, middleware, or `next/image` optimizer.
- Everything must work as a pure static export shipped from `out/`.
- Do not add server-only features (dynamic route handlers, `revalidate`, server actions) — they will silently break the export.

### Rendering model

The site is aggressively client-heavy. `app/layout.tsx` wraps children in a stack of client-only providers, in order:

`LenisProvider` → `SmoothScroll` → `UiProvider` → `ThemeProvider` → `CartProvider` → `VideoModalProvider` → `TitleSplitProvider` → `SubTitleSplitProvider`.

Component conventions that follow from this:
- Anything using hooks / effects / DOM APIs must be `"use client"`.
- Route-transition cleanup lives in `UiContext` — it listens to `usePathname()` and closes all overlays (search, side nav, mobile menu, video modal) on route change. New overlays should follow the same close-on-route-change pattern.
- Theme is applied via body classes (`active-body`, `dark-mode`). `layout.tsx` runs a small inline `<script>` before hydration to set the initial class from `localStorage.themeMode` so the first paint isn't a flash. Preserve that pattern if you touch theming.
- `SmoothScroll` disables Lenis on touch devices; `LenisContext` exposes a shared `MutableRefObject` so other components can read the Lenis instance without re-creating it.
- `TitleSplitProvider` and `SubTitleSplitProvider` walk registered heading elements, split them with `split-type`, and animate with GSAP + ScrollTrigger on scroll. Register via `TitleSplitWrapper` / `SubTitleWrapper` rather than importing GSAP directly in feature components.

### Component layout

- `app/` — Only the homepage (`app/page.tsx`) and shared `layout.tsx`. `page.tsx` is a plain composition of `components/homes/home-1/*` sections plus `Header1`, `Contact`, and `Footer1`.
- `components/homes/home-1/` — Sections specific to the demo home (`Hero`, `Services`, `Marquee`, `Features`, `About`, `Facts`, `Services2`, `Testimonials`, `Faqs`, `Blogs`, `Partners`).
- `components/headers/`, `components/footers/` — Chrome (`Header1`, `Footer1`, `Nav`, `MobileMenu`, `Sidemenu`).
- `components/common/` — Cross-cutting UI (togglers, preloader, scroll-to-top, split-text wrappers, video popup, theme button).
- `components/features/`, `components/services/`, `components/testimonials/`, `components/contact/` — Reusable variants used by the home sections.
- `context/` — All React contexts (`UiContext`, `ThemeContext`, `LenisContext`, `CartContext`, `VideoModalContext`).
- `data/` — Typed static data (menus, blog cards, services, shop products, footer, demo grid, features). This is the source of truth for content — components read from these files rather than hardcoding strings.
- `types/` — Type definitions matching `data/`.
- `utils/` — Currently only `menuActive.ts` (nav active-state helpers).
- `public/assets/` — All theme assets: `scss/` (compiled via Next's Sass support from `app/layout.tsx`'s `@import "../public/assets/scss/style.scss"`), `css/plugins/`, `images/`, `fonts/`, `webfonts/`.

### Styling

- SCSS entrypoint is `public/assets/scss/style.scss`, imported once from `app/layout.tsx`. It `@use`s modular partials (`global`, `utilities`, `header`, `elements`, `sections`) then `@import`s vendor CSS (Bootstrap, Font Awesome, Fontello, Swiper, LightGallery).
- Fonts are wired through `next/font/google` (`Sora`, `Manrope`) as CSS variables `--font-sora` and `--font-manrope` on `<body>`.
- Class names come from the original template (Bootstrap 5 grid, custom `hero-style1`, `vs-header`, etc.). Prefer editing SCSS partials over inline styles.

### TypeScript / ESLint

- Path alias `@/*` maps to the repo root (see `tsconfig.json`). Use `@/components/...`, `@/context/...`, `@/data/...`, `@/types/...`, `@/utils/...` — not relative paths across top-level dirs.
- `isotope-imagesloaded.d.ts` and `lightgallery.d.ts` are ambient module shims for untyped vendor packages. Add new shims here if you introduce another such dep.
- ESLint config disables the stock `no-unused-vars` in favor of `unused-imports/no-unused-imports` (error) and `unused-imports/no-unused-vars` (warn, with `^_` ignore pattern). Prefix intentionally unused vars/args with `_`.
